# WT-01 体重記録 実装記録

## 実装範囲

- リッチメニュー「体調を記録」は体調ハブとしてQuick Replyを出す。画像・6領域JSONは変更しない。
- ハブから「体重」を選ぶと、今日の体重入力を開始する。今後の体調項目も同じハブへ足せる。
- LINEテキスト「体重」「体重記録」、または数字だけ（例: `70.2` / `体重 70.2`）で今日の体重を確認なしに即記録する。
- 同日の再入力は訂正として新しい行を追加し、最新`recorded_at`を正本にする。
- 昨日・日付入力・目標体重は任意の補助導線として残す。
- 単位はkg。範囲は25.0〜250.0、小数第1位。未来日と1年以上前は拒否する。
- 保存後に最新値、7日平均、30日平均、任意の目標差を返す。平均は欠損日を埋めず、記録がある日だけを使う。
- 「目標体重 68」または設定ページからFirestoreに目標を保存できる。空欄保存で削除する。
- 途中保存、cancel、24時間TTL、operation IDによる冪等保存。

## 保存境界

- BigQuery `weight_logs`へ生ログをappend-onlyで保存する。集計は読み取り時に計算し、正本にしない。
- Firestore `weight_drafts/{line_user_id}`に会話途中状態と`expires_at`を置き、Terraform TTLを設定する。
- Firestore `weight_targets/{user_id}`に目標体重を置く。TTLは付けない。
- 日付はユーザーtimezoneのローカル日付。保存timestampはUTC。

## テキストルーティング

数字だけの体重入力が、体調の程度（1〜10）や設定下書きを奪わないよう、LINEテキストは次の順で処理する。

1. Strava連携
2. 手動Activity下書き
3. プロフィール下書き・コマンド
4. 体調フォローアップ（`"ignored"`でなければ終了）
5. 体重（裸の数字は今日の体重として即記録）

## privacy

- 体重の数値はアプリケーションログへ出さない。出すのは`user_id`、`measured_on`、訂正有無だけ。
- LINE確認メッセージと設定ページには本人向けに数値を表示する。

## 対象外

- リッチメニューへの「体重」領域追加（RM画像変更）
- 進捗画面へのtrend表示（PR-01）
- AI coaching contextへの体重入力（AN-01 / AI-01）
- 実績照合（PL-01D）
